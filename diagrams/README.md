## Описание слоев и потоков данных (Data Flow)

Архитектура системы жестко разделена на четыре изолированных технологических слоя:

1. **Слой интерфейса (Фронтенд):** 
   * Принимает текстовый ввод или локальный транскрипт голоса (через Web Speech API).
   * Отправляет запрос `POST /api/v1/chat/message` и блокирует интерфейс на время ожидания ответа.
   * Рендерит финальный JSON-пакет, разделяя текстовый ответ чата и интерактивные карточки корзины.

2. **Слой управления (Бэкенд-контроллер):**
   * Выполняет роль менеджера сессий и маршрутизатора.
   * Инициализирует детерминированную валидацию Паспорта Запроса программными средствами (без участия LLM).
   * Проверяет заполнение критических слотов (`location` и `dates`).

3. **ИИ-слой (LLM Core):**
   * **Ветка А (Состояние `inspiration`):** Если слоты пустые, LLM генерирует наводящий вопрос пользователю.
   * **Ветка Б (Состояние `searching`):** Если слоты заполнены, бэкенд активирует механизм **Function Calling**, передавая в OpenAI-совместимый API массив описаний доступных программных функций для поиска.
   * LLM возвращает структуру `tool_calls` с аргументами JSON, а после выполнения функции бэкендом — синтезирует финальный ответ и корзину.

4. **Слой данных (Мок-База):**
   * Изолированная In-Memory Mock DB, содержащая демонстрационные сущности отелей и транспорта.
   * Локально фильтрует данные по аргументам, переданным из механизма Function Calling, и возвращает результаты бэкенду.
