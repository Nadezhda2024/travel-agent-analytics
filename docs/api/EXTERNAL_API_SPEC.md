СПЕЦИФИКАЦИЯ ВНЕШНИХ API И ИСТОЧНИКОВ ДАННЫХ
Технический регламент интеграции внешних сервисов для бэкенд-разработчиков команды Ostrovok 2026
1. МОДУЛЬ «ОТЕЛИ И РАЗМЕЩЕНИЕ» (HOTELS CONTEXT)
1.1. Платформа Мультитур API v2
•	URL документации: https://www.multitour.ru/api_documentation/ 
•	Базовый эндпоинт: https://www.multitour.ru/api/v2/ 
•	Протокол взаимодействия: HTTP POST. Данные упаковываются в строку JSON.
•	Метод получения описания отелей: Hotel.Desc
•	Метод поиска цен и предложений: Hotel.Offers (обязательные параметры: date_begin, date_end, adult).
•	Формат авторизации: Передача статического токена доступа в секции header.token каждого JSON-запроса.
•	Специфика интеграции: Предоставляет полные справочники стран (Geo.Country), регионов (Geo.Region), курортов (Geo.Resort) и городов (Geo.City). Секция ответа всегда дублирует структуры header и request, а полезная нагрузка располагается в массиве response.
1.2. Платформа TravelLine Content API
•	URL документации: https://www.travelline.ru/dev-portal/docs/category/content-api 
•	Назначение источника: Получение статической структурированной информации о средствах размещения (отели, мини-гостиницы, апартаменты).
•	Ключевые методы: Запросы на извлечение контента отелей и постраничную навигацию (пагинацию) объектов.
•	Специфика интеграции: Используется для точного переноса реального отельного инвентаря РФ в структуру In-Memory базы. Отличается строгой валидацией типов комнат и удобств отеля.
2. МОДУЛЬ «КУЛЬТУРА, ЭКСКУРСИИ И ДОСТОПРИМЕЧАТЕЛЬНОСТИ» (ACTIVITIES CONTEXT)
2.1. Сервис Спутник8 API
•	URL документации: https://www.sputnik8.com/doc/api 
•	Базовый домен API: api.sputnik8.com 
•	Протокол взаимодействия: HTTP GET с передачей авторизационных параметров в Query string.
•	Параметры аутентификации: api_key (строка токена) и username (Email зарегистрированного партнера).
•	Основные эндпоинты: GET /v1/cities/:city_id/categories (категории в городе), GET /v1/products (список экскурсий с фильтрацией по city_id), GET /v1/events/:id (доступные сеансы ивент-активностей).
•	Специфика интеграции: Идеальный источник данных для таймлайна путеводителя. Содержит точные маркеры длительности ("duration": "3 часа") и типов передвижения (пешком, автобус, теплоход).
2.2. Сервис KudaGo API
•	URL документации: https://docs.kudago.com/api/#page:%D0%BF%D0%BE%D0%B8%D1%81%D0%BA 
•	Базовый URL: https://kudago.com/public-api/v1.4/  при проверке ссылки выдал ошибку 403 Forbidden
•	Протокол взаимодействия: HTTP GET. Не требует регистрации, ключей и токенов доступа.
•	Основные эндпоинты: /search/ (универсальный полнотекстовый поиск), /events/ (список мероприятий), /places/ (каталог культурных локаций).
•	Параметры фильтрации: location=kzn (Казань), ctype=place/event, fields (ограничение состава полей для снижения трафика), text_format=plain (получение текстов без HTML-тегов).
•	Специфика интеграции: Абсолютно открытый источник текстовых описаний и возрастных ограничений (age_restriction). Используется для семантического ИИ-анализа за счет поддержки нативных тегов объектов.
3. МОДУЛЬ «МЕЖДУГОРОДНИЙ ТРАНСПОРТ» (TRANSPORT CONTEXT)
3.1. Унифицированная платформа Travel Platform API
•	URL документации: https://travelplatform.ru/docs/ 
•	Базовый URL: https://travelplatform.ru/api/  (Production), https://test.travelplatform.ru/  при проверке ссылки выдал ошибку 500 Internal Server Error(Test)
•	Протокол взаимодействия: HTTP POST. Авторизация через заголовок Authorization: Bearer {token}.
•	Основной метод поиска: /api/avia/search
•	Структура контракта поиска: Объект originDestinations (массивы точек отправления/прибытия с указанием IATA-кодов городов) и объект passengers (количество и типы пассажиров).
•	Специфика интеграции: Агрегирует данные множества GDS (Amadeus, Galileo, SIG) и NDC-систем в единую JSON-структуру, скрывая сложность логики транспортных шлюзов.
4. МОДУЛЬ «КЛИМАТ И ПОГОДА» (WEATHER CONTEXT)
4.1. Аналитический обзор Otus Journal
•	URL публикации: https://otus.ru/journal/api-dlya-ispolzovaniya-dannyh-o-pogode-na-svoih-servisah-top-luchshih/#s2 
•	Назначение: Сравнительный анализ и архитектурные рекомендации по интеграции погодных REST-сервисов в ИИ-приложения.
4.2. Сервис Яндекс.Погода для Бизнеса
•	URL консоли: https://yandex.ru/pogoda/b2b/console/api-page 
•	Условия хакатона: Доступен бесплатный тестовый период длительностью 7 дней.
•	Специфика интеграции: Локальный коммерческий шлюз высокой точности для РФ рынка. Авторизация по Яндекс ID. Передает детальные климатические метрики по географическим координатам.
4.3. Архив Meteostat API
•	URL документации: https://dev.meteostat.net/api 
•	Базовый URL: https://meteostat.p.rapidapi.com 
•	Ограничения сети: Требуется стабильное VPN-подключение для доступа из инфраструктуры РФ.
•	Формат авторизации: Передача RapidAPI токена в HTTP-заголовке X-RapidAPI-Key.
•	Специфика интеграции: Предоставляет бесплатный лимит в 500 запросов в месяц. Специализируется на глубоких исторических архивах погоды и климатических нормах метеостанций.
4.4. Сервис Open-Meteo
•	URL документации: https://open-meteo.com/ 
•	Базовый URL: https://api.open-meteo.com/v1/ 
•	Ограничения сети: Требуется VPN-подключение для доступа из инфраструктуры РФ.
•	Лимиты тарифа: Полностью бесплатно до 10 000 API-запросов в день для некоммерческого использования.
•	Формат запроса: HTTP GET, не требует регистрации, ключей или привязки банковских карт.
•	Специфика интеграции: Сбор данных 30+ национальных метеомоделей. Запрос формируется по параметрам latitude и longitude. Возвращает блоки current (текущая ситуация) и hourly/daily (прогнозы) со строгими ISO-датами.
